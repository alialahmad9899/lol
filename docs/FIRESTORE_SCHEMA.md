# مخطط بيانات Firestore لتطبيق رُوح

هذا المخطط هو العقد بين Flutter وقاعدة البيانات ولوحة الإدارة. يجب أن تستخدم لوحة الإدارة أسماء المجموعات والحقول والقيم نفسها. توجد القواعد البرمجية في `firestore.rules`؛ وجودها في المستودع لا يعني أنها نُشرت إلى Firebase.

## 1. المستخدمون

المسار: `users/{uid}`

الحقول الأساسية:

| الحقل | النوع | ملاحظات |
|---|---|---|
| `uid` | string | يساوي UID من Firebase Authentication ولا يغيّره المستخدم |
| `email` | string | البريد المرتبط بحساب Firebase |
| `displayName` | string | الاسم، حتى 100 محرف |
| `locale` | string | `ar` أو `en` |
| `interests` | array<string> | حتى 20 اهتماماً |
| `primaryGoal` | string | الهدف الشخصي، اختياري للتوافق مع الملفات القديمة، حتى 120 محرفاً |
| `createdAt` | timestamp | يحدده الخادم |
| `updatedAt` | timestamp | يحدده الخادم |
| `schemaVersion` | number | القيمة الحالية 1 |

لا يسمح للمستخدم بتغيير UID أو البريد أو تاريخ الإنشاء أو schemaVersion أو أي دور إداري.

## 2. المديرون

المسار: `admins/{uid}`

- معرّف المستند هو UID نفسه من Firebase Authentication.
- إنشاء المدير يتم من Firebase Console فقط بعد التحقق من هوية المالك.
- يستطيع الحساب قراءة مستند UID الخاص به فقط للتحقق من صلاحية الإدارة؛ لا يستطيع قراءة القائمة.
- الإضافة والتعديل والحذف محجوبة عن كل حساب من التطبيق. إنشاء المدير الأول يتم من Firebase Console.
- لا تضف حقلاً مثل `isAdmin` داخل مستند المستخدم؛ صلاحية الإدارة مصدرها مستند المجموعة المحمية.

## 3. التصنيفات

المسار: `categories/{categoryId}`

الحقول المقترحة:

| الحقل | النوع |
|---|---|
| `title` | string |
| `description` | string |
| `sortOrder` | number |

التصنيفات تقرأ علناً، أما الإضافة والتعديل والحذف فللإدارة فقط. استخدم أسماء التصنيفات الأساسية:

- وعي
- تطوير
- استرخاء
- تركيز
- تغيير
- رُوح اليومية

## 4. المحتوى والجلسات النصية

المسار: `content_items/{contentId}`

الحقول التي تقرؤها شاشة الاستكشاف حالياً:

| الحقل | النوع | ملاحظات |
|---|---|---|
| `title` | string | عنوان المحتوى |
| `summary` أو `description` | string | وصف مختصر |
| `body` أو `content` | string | النص |
| `categoryId` | string | معرّف التصنيف |
| `type` | string | `text` أو `exercise` أو `audio` أو `video` |
| `durationMinutes` | number | اختياري |
| `tags` | array<string> | كلمات البحث |
| `sortOrder` | number | ترتيب العرض |
| `status` | string | يجب أن تكون `published` ليظهر للمستخدم |

المحتوى غير المنشور لا يظهر للمستخدم. مشغل الصوت والفيديو غير مفعّل في النسخة المجانية الحالية.

### المحفوظات وتقدم المحتوى

المسارات الخاصة بكل مستخدم:

- `users/{uid}/savedContent/{contentId}`: الحقول `contentId` و`createdAt`. تحفظ مرجع المحتوى فقط، ويُسمح للمستخدم بقراءة سجلاته وإنشائها وحذفها فقط.
- `users/{uid}/contentProgress/{contentId}`: الحقول `contentId` و`completed` و`completedAt` و`updatedAt`. يسجل التطبيق اكتمال المحتوى النصي، ويمكن للمستخدم قراءة سجلات تقدمه وتحديثها أو حذفها ضمن قواعده الخاصة.

لا يستطيع المستخدم قراءة محفوظات مستخدم آخر. ويجب أن يكون المحتوى منشوراً عند إنشاء مرجع محفوظ أو سجل إكمال.

## 5. الكورسات

المسار: `courses/{courseId}`

الحقول المعتمدة لواجهة الكورسات:

| الحقل | النوع | ملاحظات |
|---|---|---|
| `title` | string | عنوان الدورة |
| `summary` | string | وصف مختصر |
| `description` | string | وصف تفصيلي |
| `instructorName` | string | اسم المدرب |
| `level` | string | مستوى الدورة |
| `durationMinutes` | number | اختياري |
| `price` | number | استخدم 0 للمجاني |
| `currency` | string | رمز العملة |
| `isFree` | boolean | يجب أن يكون true مع price=0 للمجاني |
| `sortOrder` | number | ترتيب العرض |
| `status` | string | `published` لعرض بيانات الدورة |

**مهم:** الدورة المجانية يجب أن تحمل `isFree: true` و`price: 0` معاً. أي تعارض بين الحقلين يجعلها غير قابلة للتسجيل المجاني. للدورة المدفوعة استخدم `isFree: false` وسعراً أكبر من صفر.

### دروس الدورة

المسار: `courses/{courseId}/lessons/{lessonId}`

| الحقل | النوع |
|---|---|
| `title` | string |
| `summary` | string |
| `body` أو `content` | string |
| `type` | string: `text` أو `exercise` أو `audio` أو `video` |
| `durationMinutes` | number اختياري |
| `sortOrder` | number |

الدروس محمية؛ لا تُقرأ إلا من مدير أو من مستخدم لديه تسجيل نشط في الدورة. لا تخزن فيديو أو ملفاً صوتياً داخل Firestore.

## 6. تسجيلات الكورسات وتقدم المستخدم

المسار: `users/{uid}/enrollments/{courseId}`

الحقول:

| الحقل | النوع |
|---|---|
| `userId` | string يساوي UID |
| `courseId` | string يساوي معرّف الدورة |
| `status` | string: `active` |
| `completedLessonIds` | array<string> |
| `progressPercent` | integer من 0 إلى 100 |
| `createdAt` | timestamp من الخادم |
| `updatedAt` | timestamp من الخادم |

- المستخدم يستطيع إنشاء تسجيل ذاتي فقط عندما تكون الدورة منشورة ومجانية وفق الحقلين أعلاه.
- لا يستطيع المستخدم إنشاء تسجيل ذاتي لدورة مدفوعة.
- يستطيع المستخدم تحديث قائمة الدروس المكتملة ونسبة التقدم فقط، ولا يغيّر حالة التسجيل أو معرّف المستخدم أو الدورة.
- تسجيل الدورة المدفوعة يتم بعد مراجعة طلب الدفع واعتماده من الإدارة، وليس من التطبيق مباشرة.
- مستند تسجيل موجود بحالة غير نشطة يتطلب مراجعة إدارية قبل إعادة تفعيله.

## 7. البرامج والتحديات

المسار الأساسي: `programs/{programId}`

تقرأ الشاشة الحقول التالية: `title` و`summary` و`description` و`durationDays` و`price` و`currency` و`isFree` و`sortOrder` و`status`. تكون الدورة/البرنامج مجانياً فقط عندما `isFree: true` و`price: 0` مع حالة `published`.

### أيام البرنامج

المسار: `programs/{programId}/days/{dayId}`

الحقول: `dayNumber` و`title` و`description` و`body` و`sortOrder`. لا تُقرأ المهام إلا بعد وجود تسجيل نشط.

### تسجيل المستخدم وتقدمه

المسار: `users/{uid}/programEnrollments/{programId}`

الحقول: `userId` و`programId` و`status` و`completedDayIds` و`progressPercent` و`createdAt` و`updatedAt`. يسمح التسجيل الذاتي للبرامج المجانية فقط. المستخدم يحدّث الإنجاز والتقدم فقط؛ ولا يستطيع إنشاء تسجيل في برنامج مدفوع أو تغيير حالته.

## 8. طلبات الدفع اليدوي

المسار: `paymentRequests/{requestId}`

الحقول عند الإنشاء:

| الحقل | النوع | ملاحظات |
|---|---|---|
| `userId` | string | UID لصاحب الطلب |
| `courseId` | string | معرّف الكورس |
| `courseTitle` | string | الاسم كما هو في سجل الكورس |
| `amount` | number | السعر الحالي في سجل الكورس |
| `currency` | string | العملة الحالية في سجل الكورس |
| `transferReference` | string | مرجع التحويل النصي، من 4 إلى 120 محرفاً |
| `status` | string | `pending` عند الإرسال |
| `createdAt` | timestamp | من الخادم |
| `updatedAt` | timestamp | من الخادم |

بعد مراجعة الإدارة تضاف الحقول:

- `status`: `approved` أو `rejected`.
- `reviewNote`: ملاحظة أو سبب الرفض.
- `reviewedBy`: UID المدير الذي راجع الطلب.
- `reviewedAt`: وقت المراجعة.

**آلية الوصول:** يمكن للمستخدم قراءة طلباته فقط، بينما تستطيع الإدارة قراءة الطلبات المعلّقة. لا يمكن للمستخدم تعديل الطلب بعد إرساله أو اعتماده بنفسه. عند الموافقة، تُنشأ صلاحية الكورس في معاملة Firestore واحدة مع تحديث حالة الطلب، وتتأكد القواعد من وجود تسجيل نشط بعد المعاملة.

رقم المرجع ليس إثباتاً آلياً لوصول المال؛ يجب على المدير التحقق من التحويل خارج التطبيق قبل الموافقة. لا تتم معالجة الدفع تلقائياً ولا توجد بوابة دفع إلكترونية في هذه النسخة.

## 9. قواعد الأمان

- جميع الكتابات الإدارية محصورة بمستند مدير محمي.
- لا تعتمد على إخفاء زر في Flutter لحماية المحتوى أو المدفوعات.
- لا تسمح للمستخدم بتعديل مستند مستخدم آخر.
- لا تمنح الوصول إلى دورة مدفوعة اعتماداً على قيمة يرسلها العميل.
- اختبر القواعد على Firebase Emulator قبل نشرها، ثم اختبرها على المشروع الحقيقي بعد إنشاء Firestore.
