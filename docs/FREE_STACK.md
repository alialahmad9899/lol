# الخدمات المجانية — قرارات النسخة التجريبية

## القرارات المعتمدة

- **Firebase Spark معتمد** للحسابات وقاعدة البيانات. أضيفت حزم Flutter وطبقة تهيئة ومخازن بيانات أولية وقواعد Firestore.
- **Supabase مستبعد نهائياً** من هذا المشروع؛ لن ننشئ مشروعاً عليه ولن نستخدم أي مشروع سابق.
- **YouTube والفيديو والبث المباشر مؤجلة** وليست ضمن أول نسخة تشغيلية.
- لا نضيف بطاقة دفع، ولا نفعّل Billing أو خطة Blaze، ولا نسمح بخدمة مدفوعة أن تتحول تلقائياً إلى فاتورة.
- الاتصال الفعلي بـ Firebase لم يكتمل بعد؛ يلزم إنشاء مشروع Spark وتوليد `lib/firebase_options.dart` ونشر قواعد الأمان.

## الهيكل التقني المعتمد

| الجزء | الخيار | الاستخدام |
|---|---|---|
| تطبيق الهاتف | Flutter | Android وiOS من قاعدة كود واحدة |
| تهيئة Firebase | Firebase Core | ربط تطبيق Flutter بمشروع Firebase |
| الحسابات | Firebase Authentication | بريد وكلمة مرور، جلسات، إعادة تعيين كلمة المرور |
| قاعدة البيانات | Cloud Firestore | المستخدمون، الاهتمامات، المحتوى النصي، الدورات والتقدم |
| الإشعارات | Firebase Cloud Messaging | يضاف لاحقاً ضمن مرحلة الإشعارات |
| لوحة الإدارة | Flutter Web | واجهة منفصلة للأدوار الإدارية |
| الصور والصوت والفيديو | مؤجلة | لا نستخدم Firebase Storage لأنه يتطلب Blaze |
| الفيديو والبث | مؤجلان | لا YouTube ولا مزود بث في النسخة الحالية |
| المدفوعات | مؤجلة | نموذج طلب يدوي لاحقاً دون بوابة دفع |

## حدود الخطة المجانية

الحصص الرسمية المنشورة لـ Cloud Firestore على الخطة المجانية:
- 1 GiB بيانات مخزنة.
- 50,000 قراءة مستند يومياً.
- 20,000 كتابة يومياً.
- 20,000 حذف يومياً.
- 10 GiB نقل بيانات صادرة شهرياً.

على Spark، تجاوز حصة منتج له حد مجاني قد يوقف استخدام ذلك المنتج لبقية دورة الاستخدام؛ لا نرقّي المشروع تلقائياً ولا نضيف بطاقة لتجاوز الحد.

## قيود يجب الالتزام بها

- Firebase Storage يتطلب Blaze؛ لذلك لا نبني رفع الصور أو ملفات إثبات الدفع عليه الآن.
- Firestore يخزن البيانات المنظمة والبيانات الوصفية، وليس ملفات الوسائط.
- SMS ليس ضمن النسخة المجانية المعتمدة؛ نستخدم البريد وكلمة المرور.
- لا Cloud Functions ولا أي منتج يتطلب Blaze.
- قواعد Firestore هي خط الدفاع الحقيقي؛ إخفاء زر المدير في التطبيق ليس حماية.
- لا يستطيع المستخدم تغيير دوره من ملفه الشخصي. صلاحية المدير تُمنح يدوياً من Firebase Console.
- FCM للإشعارات فقط، ولا يمنح صلاحية الوصول إلى محتوى مدفوع.
- لا نخزن مفاتيح خدمة إدارية أو أسراراً داخل Flutter أو لوحة الإدارة.

## ما يدخل النسخة الأولى

- تسجيل حساب وتسجيل دخول وخروج بالبريد وكلمة المرور.
- الملف الشخصي والاهتمامات والأهداف.
- التصنيفات والمحتوى النصي ووصف الجلسات.
- البرامج والتحديات ذات البيانات النصية.
- قائمة الدورات والدروس وبياناتها الوصفية.
- التسجيل في الدورات المجانية وتتبع التقدم.
- واجهة طلب تسجيل/تحويل نصية ومراجعة إدارية لاحقاً.
- لوحة إدارة مع قواعد وصول فعلية على الخادم.
- الإشعارات بعد استكمال تكامل FCM.

تبقى ملفات الصوت والفيديو، الصور المرفوعة، إثباتات الدفع كصور، البث الحي، وبوابات الدفع خارج نطاق النسخة الحالية.

## قواعد منع التكاليف غير المقصودة

1. لا نفعّل Blaze أو أي خطة مدفوعة.
2. لا نضيف بطاقة أو حساب فوترة إلى Firebase.
3. لا ننشئ مورداً يتطلب Billing.
4. لا نستخدم Firebase Storage أو Cloud Functions.
5. نراقب حصص Firestore ونختبر تعامل التطبيق عند نفاد الحصة.
6. لا نضع مفاتيح خدمة إدارية في تطبيق العميل.
7. أي خدمة جديدة تمر بمراجعة رسمية للتسعير والحدود قبل استخدامها.

## تكاليف النشر المؤجلة

- يمكن توزيع APK تجريبي على Android مباشرة دون رسوم متجر.
- نشر Google Play يتطلب رسم تسجيل حساب مطور.
- نشر App Store وTestFlight يتطلب عضوية Apple Developer مدفوعة سنوياً.
- لا توجد رسوم نشر ضمن مرحلة النموذج التجريبي.
