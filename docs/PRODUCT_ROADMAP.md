# خارطة تنفيذ رُوح

هذه الخارطة مبنية على مستند الخطة المرفوع إلى المستودع. نعتمد تطويراً مرحلياً مع اختبار كل مرحلة قبل الانتقال إلى التالية.

## قرارات النطاق الحالية
- Supabase خارج المشروع.
- YouTube والفيديو والبث المباشر مؤجلة.
- لا توجد خدمات مدفوعة أو وسائل فوترة في النسخة التجريبية.
- Firebase Spark هو المرشح الأول للحسابات وقاعدة البيانات والإشعارات، ولم يُنشأ أو يُربط بعد.
- لا نستخدم Firebase Storage أو Cloud Functions؛ لأنهما يتطلبان خطة Blaze.
- لا نرفع صوراً أو ملفات في النسخة الأولى. نبدأ ببيانات نصية وواجهات كاملة، ونعيد تقييم تخزين الوسائط لاحقاً.

## المرحلة 0 — تأسيس المشروع
- إنشاء مشروع Flutter مستقل.
- تثبيت الهوية والألوان ودعم العربية واتجاه RTL.
- إضافة شاشة رئيسية أولية واختبار واجهة.
- تجهيز فحص تلقائي للكود على GitHub Actions.

## المرحلة 1 — التصميم وتجربة الاستخدام
- اعتماد خريطة التنقل لجميع الشاشات.
- إكمال الشاشات الأساسية: البداية، التعريف، التسجيل، الدخول، الرئيسية، الاستكشاف، المحتوى، الدورات، الملف الشخصي والإعدادات.
- تأجيل شاشات تشغيل الفيديو والبث الحي، مع الاحتفاظ بمكانها في خريطة التوسع لاحقاً.
- دعم الشاشات الصغيرة والكبيرة وحالات التحميل والفراغ والخطأ.
- اعتماد التصميم النهائي قبل توصيل البيانات.

## المرحلة 2 — الحسابات والبيانات
- اعتماد Firebase Spark بعد تثبيت تصميم البيانات وقواعد الأمان.
- إنشاء Authentication للبريد وكلمة المرور وإدارة الجلسة واستعادة كلمة المرور.
- تصميم Firestore للمستخدمين والملفات الشخصية والأدوار والاهتمامات والمحتوى والدورات.
- كتابة واختبار قواعد Firestore Security Rules لكل مجموعة.
- منع المستخدم من منح نفسه دور مدير أو صلاحية دورة مدفوعة.
- إعداد صلاحية مدير من مصدر موثوق غير قابل للتعديل من المستخدم.
- عدم استخدام SMS أو منتجات تتطلب Billing.

## المرحلة 3 — المحتوى النصي والجلسات
- تصنيفات: وعي، تطوير، استرخاء، تركيز، تغيير، رُوح اليومية.
- وصف الجلسة ومدتها ونوعها وتعليماتها.
- الحفظ والمفضلة والتقييم وإكمال المحتوى.
- تتبع التقدم وسجل الإنجاز.
- تأجيل رفع الوسائط وتشغيل ملفات الصوت والفيديو إلى مرحلة اختيار تخزين مجاني مناسب.

## المرحلة 4 — البرامج والكورسات
- إنشاء الكورس ووصفه وسعره ومدته ودروسه.
- كورسات مجانية ومدفوعة من ناحية بيانات العرض والتسجيل.
- التسجيل والتحقق من حق الوصول إلى الدروس بقواعد الخادم.
- تحديات وبرامج مجدولة مثل تحدي 7 أيام.
- مكتبة مشتريات المستخدم وتقدم الدروس.
- تشغيل الدروس المرئية مؤجل؛ لا نعرض درساً على أنه قابل للتشغيل قبل توفير مصدر تشغيل فعلي.

## المرحلة 5 — طلبات الدفع اليدوي
- بناء سجل طلبات منفصل عن منح صلاحية الكورس.
- تجهيز نموذج مرجع تحويل شام كاش نصي للمستخدم.
- مراجعة إدارية وقبول أو رفض مع سجل تدقيق.
- لا رفع لإثبات صورة في هذه المرحلة بسبب عدم اعتماد تخزين ملفات مجاني.
- لا تُمنح صلاحية المحتوى المدفوع اعتماداً على رسالة من التطبيق وحدها.
- تأجيل Stripe وأي بوابة دفع إلكترونية.

## المرحلة 6 — الإشعارات
- إعداد Firebase Cloud Messaging بعد إقرار مشروع Firebase Spark.
- إشعارات أساسية للتحديات والدورات وتحديثات حالة الطلب.
- تذكيرات محلية للمواعيد عند الحاجة.
- لا بث مباشر ولا تنبيهات بدء بث في هذه النسخة.

## المرحلة 7 — لوحة الإدارة
- إدارة المستخدمين والأدوار.
- إدارة التصنيفات والمحتوى والبرامج والدورات والدروس.
- مراجعة طلبات الدفع اليدوي.
- إحصاءات أساسية للتسجيلات والمبيعات والمشاهدات والتفاعل.
- سجل تدقيق للأفعال الحساسة.
- حماية كل عملية إدارية على الخادم، وليس في الواجهة فقط.

## المرحلة 8 — الاختبار والتجهيز
- اختبارات وحدات وواجهات وتكامل.
- اختبار الصلاحيات وقواعد Firestore ومحاولات الوصول غير المصرح.
- فحص الأداء واستهلاك البيانات والتعامل مع انقطاع الشبكة.
- اختبار التسجيل والدفع اليدوي وفتح المحتوى النصي والإشعارات.
- بناء APK تجريبي وتوثيق خطوات التشغيل والنسخ الاحتياطي والاستعادة.
- التحقق من عدم وجود أي خدمة مدفوعة أو إعداد Billing.

## مراحل توسعة مؤجلة بعد النسخة التجريبية
- اعتماد تخزين ملفات وصور وصوت وفيديو مجاني ضمن حد واضح.
- مشغل صوت وفيديو داخل التطبيق.
- البث المباشر للدورات.
- رفع إثباتات الدفع كصور.
- بوابات الدفع الإلكترونية.
- شهادات الإتمام والتوصيات الذكية والمجتمع الداخلي.

## قاعدة العمل
كل ميزة تُبنى من واجهة المستخدم مروراً بمستودع البيانات والخادم وقواعد الأمان حتى الاختبار. لا نعدّ الميزة منجزة لمجرد أن شكلها ظاهر في الشاشة.
