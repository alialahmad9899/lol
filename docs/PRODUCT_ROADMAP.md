# خارطة تنفيذ رُوح

هذه الخارطة مبنية على خطة المشروع الأصلية. يتم تطوير كل ميزة من الواجهة إلى البيانات وقواعد الأمان ثم الاختبار، ولا تعتبر منجزة لمجرد ظهور شكلها.

## قرارات النطاق الحالية

- Firebase Spark هو الخيار المعتمد للحسابات والبيانات.
- Supabase مستبعد.
- لا بطاقة ولا Billing ولا Blaze.
- لا Firebase Storage أو Cloud Functions في النسخة الحالية.
- YouTube والصوت والفيديو والبث المباشر مؤجلة حتى اعتماد خدمة تناسب شرط المجانية.
- طلبات الدفع اليدوي تعتمد رقم مرجع نصياً ومراجعة بشرية؛ لا يوجد تحقق مصرفي آلي ولا رفع صور أو بوابة دفع.

## المرحلة 1 — تجربة الاستخدام والهوية

- استكمال شاشة البداية والتهيئة والتعريف بالتطبيق.
- تحويل الشعار إلى أيقونة Android وiOS وأصول Splash أصلية.
- استكمال التنقل السفلي والملف الشخصي والإعدادات.
- تحسين حالات التحميل والفراغ والخطأ وحالات الشبكة.
- اختبار الشاشات الصغيرة والكبيرة وتكبير الخط وإمكانية الوصول.

## المرحلة 2 — الحسابات والملفات الشخصية

- اختبار إنشاء الحساب والدخول والخروج واستعادة كلمة المرور.
- إضافة التحقق من البريد وسياسة حذف الحساب.
- اختبار عدم تكرار ملف المستخدم وعدم الكتابة فوق بياناته عند تسجيل الدخول.
- إضافة إعدادات الخصوصية واللغة والتفضيلات.
- اختبار قواعد Firestore بمحاولات الوصول غير المصرح.

## المرحلة 3 — المحتوى والجلسات والتمارين

- استكمال أقسام: وعي، تطوير، استرخاء، تركيز، تغيير، رُوح اليومية.
- إدارة المحتوى النصي ووصف الجلسة ومدتها وتعليماتها.
- [x] إضافة المفضلة والعناصر المحفوظة وتسجيل إكمال المحتوى.
- [x] عرض المحفوظات والمحتوى المكتمل في مكتبة المستخدم.
- [ ] إضافة التقييمات وسجل تقدم وإحصاءات أوسع وربطها بلوحة الملف الشخصي.
- تشغيل الصوت والفيديو مؤجل إلى أن تتوفر خدمة مجانية ملائمة.

## المرحلة 4 — البرامج والتحديات والكورسات

- بناء قائمة البرامج والتحديات المجدولة مثل تحدي 7 أيام.
- استكمال التسجيل في البرامج ومهام الأيام وتتبع الإنجاز.
- تطوير الدورات المجانية والمدفوعة ودروسها.
- استكمال مكتبة المستخدم وحقوق الوصول والتقدم.
- إبقاء الدروس المدفوعة محمية بقواعد Firestore، وعدم منحها من التطبيق مباشرة.
- تأجيل تشغيل الدروس المرئية إلى حين توفير مصدر وسائط معتمد.

## المرحلة 5 — طلبات الدفع اليدوي

- [x] طلب تسجيل منفصل عن منح صلاحية الدورة.
- [x] إدخال مرجع تحويل شام كاش النصي.
- [x] حالات pending / approved / rejected مع ملاحظة المراجعة.
- [x] إنشاء وصول للدورة المدفوعة من مراجعة إدارية داخل معاملة Firestore واحدة.
- [ ] اختبار سير الطلب كاملاً على Firebase الحقيقي بعد نشر القواعد.
- لا Stripe ولا بوابات مدفوعة في النسخة المعتمدة حالياً.
- لا رفع إثباتات صور بسبب استبعاد التخزين المدفوع.

## المرحلة 6 — الإشعارات

- إضافة Firebase Cloud Messaging بعد استقرار الحسابات والبيانات.
- إشعارات التحديات والدورات وتغيّر حالة الطلب.
- تذكيرات محلية للمواعيد.
- لا تنبيهات بث مباشر في النسخة الحالية.

## المرحلة 7 — لوحة الإدارة

- [x] لوحة إدارة أولية داخل التطبيق لإدارة التصنيفات والمحتوى والجلسات.
- [x] إدارة البرامج والتحديات والكورسات والدروس والأيام.
- [x] مراجعة طلبات الدفع اليدوي للكورسات.
- [ ] تحويل/توسيع لوحة الإدارة إلى لوحة ويب مستقلة.
- [ ] إدارة المستخدمين والأدوار والتسجيلات من لوحة الإدارة.
- [ ] إحصاءات أساسية وسجل تدقيق.
- حماية عمليات الإدارة من الخادم، وليس من إخفاء الأزرار فقط.

## المرحلة 8 — الاختبار والتجهيز

- اختبارات وحدات وواجهات وتكامل.
- اختبار قواعد Firestore على المحاكي وعلى المشروع الحقيقي.
- اختبار الوصول إلى الدروس المدفوعة ومنع التحايل على حالة التسجيل.
- فحص الأداء واستهلاك البيانات والعمل مع ضعف الشبكة.
- بناء APK/AAB Release، وإعداد التوقيع، وتجهيز iOS على macOS.
- توثيق النسخ الاحتياطي والاستعادة وسياسات الخصوصية والشروط.
- التحقق من عدم وجود أي خدمة مدفوعة أو إعداد Billing.

## قاعدة العمل

كل ميزة تُبنى من واجهة المستخدم مروراً بمستودع البيانات وقواعد الأمان حتى الاختبار. أي تكامل غير مختبر مع Firebase الحقيقي يبقى معلّماً بأنه غير متحقق.
